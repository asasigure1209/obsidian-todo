## 1. 何を作るか

Obsidian の中で動く、**1日単位のカンバン型TODOボード**（Obsidian プラグイン）。

### 本質的価値

> 1日の仕事を迷わず組み替えながら進め、終業時には振り返り（Good/Bad/Try）の事実がそろっている。

### 価値命題

> 変わり続ける1日を、迷わず組み替え、そのまま振り返れる。

- **対象：** Claude と業務を進め、日報で振り返る個人（本人。GTD とは別運用）
- **置き換える手段：** 紙のTODO ＋ Googleカレンダー

### 価値の階層

| 層 | 内容 |
|---|---|
| L1 表層の要求 | 列で動かし、順番を入れ替えたい |
| L2 機能的価値 | 列の中の順番＝今の優先度／未完了は翌日へ自動で複製／作業時間をポモドーロ単位で記録 |
| L3 情緒的価値 | 優先度が変わっても組み替えられる安心／判断は自分がしているコントロール感／終業時に1日を振り返れる納得感 |
| L4 本質的価値 | 上記「本質的価値」 |

## 2. 利用者と前提

| 項目 | 内容 |
|---|---|
| 利用者 | 本人1名。ボードの操作（追加・並べ替え・完了）はすべて本人が行う |
| Claude との関係 | 朝、本人の指示で Claude がその日の TODO ファイルを作る（前日の未完了の複製、Googleカレンダーの予定、追加の TODO）。日中のボード操作はしない。終業後は Markdown に残った記録と作業ログを**読んで**振り返りの分析を手伝う |
| 端末 | PC のみ（モバイル対応は不要） |
| GTD | 別運用。このツールの列や用語に GTD の分類は持ち込まない |
| 日報 | 終業前に本人が `日報/` フォルダに Good/Bad/Try を書く。ツールは日報に書き込まない |
| データの所有 | 自分の Vault 内の Markdown。プラグインがなくても読める形で残す |

### ヒアリングで分かった現状（2026-11-03〜04、本人）

- TODOは紙に書いている。朝は Googleカレンダーの予定と前日のTODOを見て、今日やることを決める
- 前日の残りは毎日紙に書き写している
- 紙で困っていること
  - 優先度が変わっても順番を入れ替えられない
  - 電子データとして残らず、後から Claude で分析できない
  - 実際にどれだけ時間がかかったかが後から分からない
- 前職で Obsidian プラグインを作り、TODO管理自体はうまくいった。ただし時間計測は開始・終了を自分で押す方式で、**押し忘れ・止め忘れにより計測できなかった**。業務で作ったため退職時に持ち出せなかった
- 作業は途切れ途切れになりがち

## 3. スコープ

### 含む

1. TODOの追加（名前と見積もり）
2. 並べ替え（列の中の順番＝優先度）
3. 列の移動（今日やる → 着手中 → 完了）
4. 着手中に動かすとポモドーロ（25分）のタイマーが始まる
5. 作業時間を分単位で修正・追加する
6. 今日の予定をタイムラインで表示（Claude が Googleカレンダーから取得して TODO ファイルに書いた予定）
7. 終業の振り返り画面（完了数、作業時間、見積もりとの差）と日報ファイルを開く導線
8. 未完了TODOを翌日のリストへ複製

### 含まない（実装を軽くするために意図的に外したもの）

| 外したもの | 理由・代わり |
|---|---|
| 持ち越し回数の表示 | 実装コスト。未完了は単純に翌日へ複製するだけ |
| TODOの分割 | 実装コスト |
| 追加時の「入れる場所」の選択 | 末尾に追加し、ボード上で並べ替えれば足りる |
| 追加時の関連ノート | 不要と判断 |
| サブエージェント実行・エージェント実行時間の表示 | 今回の範囲外。将来の拡張候補（9章） |
| 日報への自動書き込み | 日報は本人が書く。ツールは開くだけ |
| モバイル対応 | PC のみで使う |
| GTD 連携 | 別運用。当日の状況を GTD にメモすることはあっても、ツールの役割ではない |

## 4. 設計原則

| # | 原則 | 根拠 |
|---|---|---|
| P1 | **並べ替えは主役の操作。** 列の中の順番が、そのまま今の優先度 | 紙では優先度が変わっても入れ替えられない |
| P2 | **実体は自分の Vault の Markdown。** 手元に残り続け、Claude がそのまま読んで分析できる | 前職で作ったプラグインは持ち出せずに失った／後から Claude で分析したい |
| P3 | **日中の操作はすべて人。** 追加・並べ替え・完了は本人が行う。朝のファイル作成だけは、本人の指示で Claude が行う | 「一旦、自分でやりたい」／朝は Claude と予定を見ながら TODO を組み立てる運用／実装を軽くする |
| P4 | **時間はポモドーロで測り、分で直す。** 25分で自動終了し、途切れ途切れの実情は分数で修正できる | 前職で止め忘れて計測できなかった／作業は途切れがち |
| P5 | **振り返りの材料がそろう。書くのは本人。** | 終業前に日報フォルダへ Good/Bad/Try を書いている |

共通する考え方：**自動で記録し、人が後から直せる。** 記録が欠けると信用できなくなり、使われなくなる（前職の失敗）。自動記録を基本にしつつ、直せる余地を残して記録への信頼を保つ。

## 5. 画面仕様

モックはキャンバスの M1〜M4 を参照。表示しているタスクや数値はすべてサンプル。

### M1 今日のボード（メイン画面）

**ヘッダー**
- 日付と前日・翌日への移動
- 今日の集中ポモドーロ数（完了数 / 予定の合間で可能な数）と進捗バー
- 作業ログ（`作業ログ/YYYY-MM-DD.md`）へのリンク
- 「終業の振り返り」ボタン → M3

**左サイドバー**
- 今日の予定を 9:00〜18:00 のタイムラインで表示。予定はブロックで描く
- 現在時刻を赤い線で示す
- 「この後、予定の合間で集中できる時間（ポモドーロ数）」を表示
- 「＋ TODOを追加」ボタン → M4

**ボード（3列）**
- **今日やる：** 上ほど優先。番号とドラッグ用のつまみ、見積もりを表示
- **着手中：** 同時に1件だけ。円形のタイマー、残り時間、何個目のポモドーロか（そのカードの `ポモドーロ` の行の数＋1。中断と手動は数えない）、見積もり。「中断（割り込み）」「完了にする」ボタン。タイマー停止中は「次のポモドーロを開始」と「完了にする」ボタン（モックの Tweaks で「計測中／停止中」を切り替えて確認できる）。案内文「カードをここへ動かすとタイマーが始まります」
- **完了：** 取り消し線で表示。作業時間と見積もり、「時間を修正」リンク → M2

### M2 作業時間を修正（ダイアログ）

- 時刻ではなく**分数**で記録・入力する（作業は途切れ途切れなので、開始・終了時刻は管理しない）
- 記録の一覧：分数（数値入力）、種類（ポモドーロ／中断したポモドーロ／手動）、メモ、削除ボタン
- 追加：「＋5分」「＋15分」「＋25分（1ポモドーロ）」、任意の分数の入力
- 合計を「62分 ≒ 2.5ポモドーロ」のように分とポモドーロの両方で表示
- 手で直した記録には「手動」の印がつく

### M3 終業の振り返り

- 完了数（例：5 / 7）、人の集中時間（ポモドーロ数＋中断回数）
- 見積もりと実績（実際の作業時間）の一覧と、その差（超過・早く完了）
- 「未完了のN件は、今日のリストに残したまま明日のリストへ複製されます」という案内
- 日報を書く材料（作業ログへのリンク、目立った出来事）と「日報/YYYY-MM-DD.md を開く」ボタン。**日報には書き込まない**

### M4 TODOを追加（ダイアログ）

- やること（テキスト）
- 見積もり：小（〜25分）／1（25分）／2（50分）／3（75分）／4+（100分〜）から選ぶ
- 「今日やる」の**いちばん下**に追加される

### テーマ（ライト／ダーク）

- **Obsidian 本体のテーマに追従する。** プラグイン独自の切り替えスイッチは設けない。Obsidian でライト／ダークを切り替えると、ボードと各ダイアログもその場で切り替わる
- 利用者が使っている Obsidian のテーマ（コミュニティテーマを含む）になじむ見た目にする
- モックは M1〜M4 の Tweaks で「ライト／ダーク」を切り替えて確認できる。下の表はモックの配色で、色の役割と意図を示す目安

| 用途 | ライト | ダーク | 備考 |
|---|---|---|---|
| 背景 | `#F6F6F3` | `#1A1A19` | |
| カード・ダイアログ | `#FFFFFF` | `#252524` | |
| 本文 | `#1C1C1A` | `#ECECE6` | |
| 補足文字 | `#5B5B57` | `#A3A39C` | どちらも背景に対して 4.5:1 以上 |
| アクセント（タイマー、進捗、予定の縁） | `#2F4BB8` | `#6F88EC` | |
| 現在時刻の線 | `#D92D20` | `#FF6B5E` | |
| 見積もり超過 | `#9A3412` | `#F0A070` | |
| 早く完了 | `#0F5C4C` | `#6FD3B4` | |
| 主ボタン | 黒地に白字 | 明るい地に黒字 | ダークでは明暗を反転させる |

## 6. 1日の流れ

1. **朝：** Claude に指示して、その日のファイルを作ってもらう（前日の未完了の複製、Googleカレンダーの予定、追加の TODO）。ボードを開き、予定のタイムラインと残り集中時間を見ながら、並べ替えて今日の順番を決める
2. **作業：** カードを着手中へ動かすとタイマーが始まる。25分で自動終了して通知が出て、作業時間が記録される。続けるときは「次のポモドーロを開始」を押す
3. **割り込み：** 「中断」で止めると、それまでの分数が「中断」として記録される。カードは着手中に残り、「次のポモドーロを開始」で再開する
4. **完了：** 「完了にする」（または完了列へ移動）でタイマーが止まり、経過分が記録される
5. **修正：** 押し忘れや途切れた作業は、M2 で分数を直す・足す
6. **終業：** M3 で見積もりとの差を確認し、日報ファイルを開いて本人が Good/Bad/Try を書く
7. **翌日：** 未完了は翌日のファイルへ複製される（当日のファイルはそのまま残る）

## 7. データ構造

基本方針：**1日1ファイルの Markdown に、確定した事実だけを書く。Markdown が唯一の正。**

### 7.1 ファイル配置

```
TODO/
  2026-11-03.md      ← プラグインが読み書き
作業ログ/
  2026-11-03.md      ← Claude と本人が書く（プラグインはリンクするだけ）
日報/
  2026-11-03.md      ← 本人が書く（プラグインは開くだけ）
```

- フォルダ名は設定で変更できる
- 3つは**同じ日付のファイル名**でつながる

### 7.2 TODOファイルの形式

```markdown
---
date: 2026-11-03
events:
  - 10:00-11:00 定例
  - 14:00-15:00 API設計レビュー
---
- [/] 提案資料の構成を固める [est:: 3]
    - 25分 ポモドーロ
- [ ] API設計レビューの指摘に対応 [est:: 2]
- [ ] 見積もりの返信を書く [est:: 1]
- [x] 経費精算を提出 [est:: 小]
    - 12分 ポモドーロ
- [x] メールの返信 [est:: 1]
    - 25分 ポモドーロ
    - 12分 中断 チャットでの問い合わせ
    - 25分 手動
```

- **TODO 1件 ＝ トップレベルのチェックボックス1行**
- **行の順番 ＝ 優先度。** 列の中の順番は、同じ状態の行どうしの並び順
- プラグインがなくても Obsidian でチェックリストとして読め、Dataview でも集計できる

### 7.3 予定

frontmatter の `events` に、その日の予定を1件1行で書く。書くのは Claude（Googleカレンダーから取得）。

```
  - {開始 HH:MM}-{終了 HH:MM} {予定名}
```

- プラグインは読んで表示するだけで、書き換えない
- 終日の予定は書かない（タイムラインに載らないため）
- 書式から外れた項目は表示せず、そのまま残す
- 日中に予定が変わったら、Claude に頼んで書き直してもらう

### 7.4 状態

| 記号 | 状態 | 備考 |
|---|---|---|
| `[ ]` | 今日やる | |
| `[/]` | 着手中 | 同時に1件だけ |
| `[x]` | 完了 | |

カードを列間で動かす ＝ 行の記号を書き換える。

### 7.5 見積もり

行末の Dataview インラインフィールド `[est:: 値]`。値は `小` `1` `2` `3` `4`（単位はポモドーロ＝25分。`4` は「4以上」を表す）。省略してもよく、その TODO は見積もりなしとして扱う。

### 7.6 作業時間

TODO 行の子の行に、1件ずつ書く。

```
    - {分}分 {種類} {メモ（任意）}
```

| 種類 | 書く主体 | 意味 |
|---|---|---|
| `ポモドーロ` | タイマー | 25分の満了、または途中で完了したときの経過分 |
| `中断` | タイマー | 「中断」で止めたときの経過分 |
| `手動` | 本人（M2） | 手で追加・修正したもの |

- **実際の作業時間（実績）＝ 子の行の分数の合計。** 合計値は保存しない
- 例：「メールの返信」は 25＋12＋25 ＝ 62分

### 7.7 Markdown に書かないもの

| もの | 置き場所・扱い |
|---|---|
| 実行中のタイマー | Markdown には書かない。終わった時点で分数を確定して Markdown に書く。Obsidian を閉じても計測中の状態（対象TODOと開始時刻）は失われない |
| 実績の合計 | 子の行から毎回計算する |
| 予定の取得元 | Googleカレンダーへの接続はプラグインが持たない。Claude が取得して `events`（7.3）に書く |
| 設定（フォルダ名、就業時間、音のオン・オフなど） | Markdown には書かない |
| 日報への書き込み | しない。M3 から日報ファイルを開くだけ |

### 7.8 翌日への複製

その日のファイルは、朝に **Claude が作る**。下のルールは Claude が守るもの。Claude を使わない日のために、ファイルがないときボードに「今日のファイルを作る」ボタンを出し、押すと同じルールで複製だけを行う（自動では作らない）。

1. その日のファイルを作る
2. **直近の過去ファイル**から `[ ]` と `[/]` の行を、順番を保って複製する（週末を挟んでも直近のファイルから）
3. 状態は `[ ]` に戻す。見積もりは残す。作業時間の子の行はコピーしない
4. 元のファイルは書き換えない（未完了のまま残る）

## 8. 詳細な振る舞い

### 8.1 タイマー

タイマーの状態は「停止中」と「計測中」の2つ。計測中のタイマーは常に1つで、着手中のカード（`[/]`）に紐づく。

| きっかけ | 記録 | カード | タイマー |
|---|---|---|---|
| カードを着手中へ動かす | — | `[/]` になる | 計測開始 |
| 25分たつ | `25分 ポモドーロ` | **着手中に残る** | 停止。カードに「次のポモドーロを開始」ボタンが出る |
| 「次のポモドーロを開始」 | — | 着手中のまま | 計測開始 |
| 「中断（割り込み）」 | `{経過分}分 中断` | **着手中に残る** | 停止。「次のポモドーロを開始」で再開できる |
| 「完了にする」／完了列へ移動 | 計測中なら `{経過分}分 ポモドーロ` | `[x]` になる | 停止 |
| 計測中に**別のカード**を着手中へ動かす | 前のカード：`{経過分}分 中断` | 前のカードは**今日やるの先頭**へ戻り `[ ]` に。新しいカードが `[/]` に | 新しいカードで計測開始 |
| 停止中に別のカードを着手中へ動かす | — | 前のカードは今日やるの先頭へ戻る | 新しいカードで計測開始 |
| 着手中のカードを今日やるへ戻す | 計測中なら `{経過分}分 中断` | `[ ]` になる | 停止 |

- **25分の満了の知らせ：** クリックするまで消えない Obsidian 内の通知＋OS の通知（macOS の通知センターなど）＋短い音。文言には何のカードの25分が終わったかを入れる。OS の通知をクリックすると Obsidian が前面に出る。音は設定でオフにできる
- **休憩：** ツールでは管理しない（休憩タイマーや自動再開はしない。自動再開は「止め忘れ」を生むため）
- **分の扱い：** 経過時間は分未満を切り捨てる。**1分未満は記録しない**
- **ボードを閉じていても進む：** Obsidian が動いていれば、ボードのタブを閉じていてもタイマーは進み、25分の満了で記録して知らせる
- **対象が見つからないとき：** 着手中の行（`[/]`）が見つからない・2件ある・文字列が違うときは、すぐには捨てずに保留にする。判定するのはタイマーを動かす操作と25分の満了のときだけで、保留中はファイルが変わるたびに読み直し、見つかれば続ける（25分を過ぎていれば確定する）。保留中の操作でも見つからなければ捨てて知らせる（記録しない）
- **Obsidian を閉じた・PC がスリープした場合：** 開始時刻から再計算する
  - 再開時に25分を過ぎていれば `25分 ポモドーロ` として確定し、停止する
  - 25分以内なら、そのまま続きから計測する
  - 実態と合わない記録は M2 で本人が直す

### 8.2 タイムラインと集中できる時間

- **就業時間を設定で指定する**（例：9:00〜18:00）。昼休みなどの休憩時間帯も設定できる
- タイムラインの表示範囲は就業時間に合わせる
- 「この後、集中できる時間」＝ 現在時刻から就業終了までのうち、予定と休憩を除いた時間。25分で割ってポモドーロ数も出す（端数は切り捨て）

### 8.3 他の日のボード

| 日 | できること |
|---|---|
| 今日 | すべての操作 |
| 過去 | 閲覧と、作業時間の修正（M2）だけ。追加・並べ替え・状態の変更はできない |
| 未来 | 開けない（翌日への移動ボタンは今日で止まる） |

### 8.4 Markdown を直接編集した場合

- Markdown を直接編集すると、その内容がボードに反映される
- **書式から外れた行は無視してそのまま残す。** ボードには出さず、プラグインがファイルを書き換えるときも消さずに元の位置に保持する

### 8.5 書式についての決定

- 着手中の記号は `[/]` のまま進める。標準の Obsidian では完了のように表示されることがあるが、ボードで操作する前提なので許容する。問題が出たら見直す
- 作業時間の書式は日本語（`25分 ポモドーロ`）のまま進める。人と Claude の読みやすさを優先する
- 「作業ログ」の書式は自由。プラグインはリンクするだけで、中身は読まない
- TODO 行は、字下げなしの `- [ ]` `- [/]` `- [x]` で始まる行だけ。`[X]`、`[-]`、`*` や `1.` で始まるチェックボックスは書式外の行として残す
- 作業時間の行を書き足すときの字下げは、そのブロックの既存の子の行に合わせる。子の行がなければスペース4つ

### 8.6 カードを動かしたときの位置

| 操作 | 入る位置 |
|---|---|
| ドラッグで並べ替える・列を移す（着手中以外） | ドロップした位置 |
| 着手中へ動かしたカード | Markdown の行は元の位置のまま、記号だけ変わる（着手中は1件なので列の中の位置はない） |
| 「完了にする」ボタン | 完了の末尾 |
| 計測中・停止中に別のカードを着手中へ動かしたときの前のカード | 今日やるの先頭（8.1） |
| TODO の追加（M4） | 今日やるの末尾 |
