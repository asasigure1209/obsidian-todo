## 1. 何を作るか

Obsidian の中で動く、**1日単位のカンバン型TODOボード**（Obsidian プラグイン）。

### 本質的価値

> 1日の仕事を迷わず組み替えながら進め、終業時には振り返り（Good/Bad/Try）の事実がそろっている。

### 価値命題

> 変わり続ける1日を、迷わず組み替え、そのまま振り返れる。

- **対象：** Claude と業務を進め、日報で振り返る個人（本人。GTD とは別運用）
- **置き換える手段：** 紙のTODO ＋ Googleカレンダー

### 価値の階層

| 層 | 内容 |
|---|---|
| L1 表層の要求 | 列で動かし、順番を入れ替えたい |
| L2 機能的価値 | 列の中の順番＝今の優先度／未完了は翌日へ自動で複製／作業時間をポモドーロ単位で記録 |
| L3 情緒的価値 | 優先度が変わっても組み替えられる安心／判断は自分がしているコントロール感／終業時に1日を振り返れる納得感 |
| L4 本質的価値 | 上記「本質的価値」 |

## 2. 利用者と前提

| 項目 | 内容 |
|---|---|
| 利用者 | 本人1名。ボードの操作（追加・並べ替え・完了）はすべて本人が行う |
| Claude との関係 | 朝、本人の指示で Claude がその日の TODO ファイルを作る（前日の未完了の複製、Googleカレンダーの予定、追加の TODO）。日中のボード操作はしない。終業後は Markdown に残った記録と作業ログを**読んで**振り返りの分析を手伝う |
| 端末 | PC のみ（モバイル対応は不要） |
| GTD | 別運用。このツールの列や用語に GTD の分類は持ち込まない |
| 日報 | 終業前に本人が `日報/` フォルダに Good/Bad/Try を書く。ツールは日報に書き込まない |
| データの所有 | 自分の Vault 内の Markdown。プラグインがなくても読める形で残す |

### ヒアリングで分かった現状（2026-11-03〜04、本人）

- TODOは紙に書いている。朝は Googleカレンダーの予定と前日のTODOを見て、今日やることを決める
- 前日の残りは毎日紙に書き写している
- 紙で困っていること
  - 優先度が変わっても順番を入れ替えられない
  - 電子データとして残らず、後から Claude で分析できない
  - 実際にどれだけ時間がかかったかが後から分からない
- 前職で Obsidian プラグインを作り、TODO管理自体はうまくいった。ただし時間計測は開始・終了を自分で押す方式で、**押し忘れ・止め忘れにより計測できなかった**。業務で作ったため退職時に持ち出せなかった
- 作業は途切れ途切れになりがち

## 3. スコープ

### 含む

1. TODOの追加（名前と見積もり）
2. 並べ替え（列の中の順番＝優先度）
3. 列の移動（今日やる → 着手中 → 完了）
4. 着手中に動かすとポモドーロ（25分）のタイマーが始まる
5. 作業時間を分単位で修正・追加する
6. 今日の予定をタイムラインで表示（Claude が Googleカレンダーから取得して TODO ファイルに書いた予定）
7. 終業の振り返り画面（完了数、作業時間、見積もりとの差）と日報ファイルを開く導線
8. 未完了TODOを翌日のリストへ複製

### 含まない（実装を軽くするために意図的に外したもの）

| 外したもの | 理由・代わり |
|---|---|
| 持ち越し回数の表示 | 実装コスト。未完了は単純に翌日へ複製するだけ |
| TODOの分割 | 実装コスト |
| 追加時の「入れる場所」の選択 | 末尾に追加し、ボード上で並べ替えれば足りる |
| 追加時の関連ノート | 不要と判断 |
| サブエージェント実行・エージェント実行時間の表示 | 今回の範囲外。将来の拡張候補（9章） |
| 日報への自動書き込み | 日報は本人が書く。ツールは開くだけ |
| モバイル対応 | PC のみで使う |
| GTD 連携 | 別運用。当日の状況を GTD にメモすることはあっても、ツールの役割ではない |

## 4. 設計原則

| # | 原則 | 根拠 |
|---|---|---|
| P1 | **並べ替えは主役の操作。** 列の中の順番が、そのまま今の優先度 | 紙では優先度が変わっても入れ替えられない |
| P2 | **実体は自分の Vault の Markdown。** 手元に残り続け、Claude がそのまま読んで分析できる | 前職で作ったプラグインは持ち出せずに失った／後から Claude で分析したい |
| P3 | **日中の操作はすべて人。** 追加・並べ替え・完了は本人が行う。朝のファイル作成だけは、本人の指示で Claude が行う | 「一旦、自分でやりたい」／朝は Claude と予定を見ながら TODO を組み立てる運用／実装を軽くする |
| P4 | **時間はポモドーロで測り、分で直す。** 25分で自動終了し、途切れ途切れの実情は分数で修正できる | 前職で止め忘れて計測できなかった／作業は途切れがち |
| P5 | **振り返りの材料がそろう。書くのは本人。** | 終業前に日報フォルダへ Good/Bad/Try を書いている |

共通する考え方：**自動で記録し、人が後から直せる。** 記録が欠けると信用できなくなり、使われなくなる（前職の失敗）。自動記録を基本にしつつ、直せる余地を残して記録への信頼を保つ。

## 5. 画面仕様

モックはキャンバスの M1〜M4 を参照。表示しているタスクや数値はすべてサンプル。

### M1 今日のボード（メイン画面）

**ヘッダー**
- 日付（「11月10日（火）」）と、前日・翌日への移動（「前の日」「次の日」）。押すとその日のボードに切り替わる。今日のボードでは「次の日」を押せない（未来の日は開けない。8.3）。その日のファイルがなければ、ファイルがないことを出す
- タブの見出しは、今日は「今日のボード」、過去の日は「11月9日のボード」。どの日を見ているかをタブでも分かるようにする
- 集中ポモドーロ数（完了数 / 可能な数）と進捗バー。過去の日にも出す
  - 完了数は、その日のすべてのカードの `ポモドーロ` の行の数。中断と手動は数えない（「何個目のポモドーロか」と同じく、25分を区切りとして数える）
  - 可能な数は、就業時間の全体（9:00〜18:00）から予定と休憩を除いた時間を25分で割り、切り捨てた数（8.2）。今の時刻に左右されず、1日の中で変わらない（「この後」の数で割ると、時間がたつほど分母が減り、進み具合が読めなくなる）
  - バーは 完了数 / 可能な数 の割合で、可能な数を超えたら満たしたまま止める。可能な数が 0 の日は空のまま
- 作業ログ（`作業ログ/YYYY-MM-DD.md`）へのリンク（「作業ログ 2026-11-10」）。押すとそのファイルを開く。ファイルがなければ、ほかのリンクと同じく Obsidian が作る（プラグインは中身を読まない。8.5）。フォルダは設定で変えられる（既定は「作業ログ」。設定画面）
- 「終業の振り返り」ボタン → M3。その日のファイルを読めた日に出す（過去の日も振り返れる）。ファイルがない日・読めない日は出さない

**左サイドバー**
- 今日の予定を就業時間（例：9:00〜18:00）のタイムラインで表示。予定はブロックで描き、予定名と開始時刻を出す。就業時間からはみ出す分は切って描く。重なった予定は重ねて描く。休憩は描かない
- 現在時刻を赤い線で示す（今日のボードで、就業時間の中のときだけ）
- 「この後、予定の合間で集中できるのは約 3.5時間（8ポモドーロ）」の形で表示（8.2）。今日のボードだけに出し、就業時間を過ぎたら「今日の就業時間は終わりました」と出す
- 「＋ TODOを追加」ボタン → M4。サイドバーのいちばん下に置く。過去の日には出さない（8.3）

**ボード（3列）**
- 列は枠や背景を持たず、ボードの背景の上にカードを並べる。列の見出しは「今日やる 4」のように件数を添える（モック M1）
- **今日やる：** 上ほど優先（見出しの右に「上ほど優先」）。カードの左の帯に番号と、その下にドラッグ用のつまみ（6つの点）。右に名前と、その下に「見積 X」
- **着手中：** 同時に1件だけ。アクセント色の太い枠で、名前は太字
  - 計測中：円形のタイマー（大きな残り時間を横に）と「N個目のポモドーロ ／ 見積 X」。N はそのカードの `ポモドーロ` の行の数＋1（中断と手動は数えない）。「中断（割り込み）」「完了にする」を横に並べる
  - 停止中：リングは灰色で満たし、残り時間の代わりに「停止中」。「N個目が終わりました ／ 見積 X」（N は `ポモドーロ` の行の数。0 なら「見積 X」だけ）。「次のポモドーロを開始」（アクセント色、再生の印）と「完了にする」を縦に並べる
  - 作業した分数は着手中のカードには出さない（モックにない。M2 で見られる）
  - 案内文「カードをここへ動かすとタイマーが始まります」は、カードがあってもなくても列のいちばん下に出す
  - モックの Tweaks で「計測中／停止中」を切り替えて確認できる
- **完了：** 名前を補足の色の取り消し線で表示。「実績 N分 ／ 見積 Y」と、「時間を修正」リンク → M2
- 見積もりのない TODO は「見積 X」を出さない（完了は「実績 N分」だけ）
- 「時間を修正」は、今日やる・着手中のカードにも見積もりの行の右に出す（中断の記録や、押し忘れた分を足すため）

### M2 作業時間を修正（ダイアログ）

- 時刻ではなく**分数**で記録・入力する（作業は途切れ途切れなので、開始・終了時刻は管理しない）
- 記録の一覧：分数（数値入力）、種類と補足、削除ボタン。メモは入力しない（今のメモは残す）

  | 種類（Markdown） | 種類の表示 | 補足 |
  |---|---|---|
  | `ポモドーロ` | ポモドーロ | 自動で記録 |
  | `中断` | 中断したポモドーロ | 割り込み：メモ |
  | `手動` | 手動 | メモ（なければ「手動で修正」） |

- 追加：「＋5分」「＋15分」「＋25分（1ポモドーロ）」、任意の分数の入力（Enter）。足した記録は `手動`
  - 任意の欄は、足せる分数（1以上の整数）なら Enter で行を足して欄を空にする。足せない分数（0、小数など）は打っている間から欄の下に問題を出し、Enter では足さずに値を残す。空欄で Enter を押しても足さずに問題を出す
  - 任意の欄に値が残っている間は「保存」を押せず、欄の下に「Enter で追加してください」と出す。入れたつもりの分が、黙って捨てられたり黙って書かれたりしない
- 合計を「62分 ≒ 2.5ポモドーロ」のように分とポモドーロの両方で表示。ポモドーロは小数1桁に四捨五入
- **「保存」で1回だけ書き込む。** それまでは下書きで、「キャンセル」・閉じるボタン・Esc で取りやめる。0分や空欄の行があれば保存できない
- 分数を変えた記録は `手動` になる（手で直した記録には「手動」の印がつく）。分数を変えなければ種類は変わらない
- 開いている間にタイマーが記録を足しても、保存で消さない。開いたときの記録が直接編集で変わっていたら、書かずに知らせ、ダイアログは開いたままにする

### M3 終業の振り返り

- ヘッダーの「終業の振り返り」で、**ボードのタブの中身を振り返りに切り替える**（ダイアログではない）。左上の矢印（「ボードに戻る」）でボードに戻る。見出しは「終業の振り返り — 11月3日（火）」
- 見るだけで、何も書き込まない。開いている間にファイルが変わったら読み直す。ファイルがなくなった・読めなくなったら、ボードと同じ知らせを出す
- 左に「完了」「人の集中時間」の2つの数と「見積もりと実績」の表、右に「日報を書く」（濃い色の枠）を置く（モック M3）
- 過去の日の振り返りでは、文言の「今日」を「この日」、「明日」を「翌日」にする（「この日の実績と…」「この日のリストに残したまま翌日のリストへ複製されます」。ボードの知らせと同じ考え方）

**完了**
- 完了の数 / その日の TODO の数（3列の合計）。例「5 / 7」

**人の集中時間**
- その日のすべてのカードの `ポモドーロ` と `中断` の分の合計を「3h 05m」の形で出す（1時間未満は「45m」）。`手動` は数えない（タイマーで測った時間だけ）
- 下に「ポモドーロ 7 ＋ 中断 2回」（それぞれの行の数。ポモドーロの数はヘッダーの完了数と同じ）

**見積もりと実績**
- 完了した TODO だけを、完了の列の順に並べる（差は終わったものにしか出せない）。列は TODO・見積・実績・差。単位はポモドーロ（25分）
- 実績は作業時間の合計（手動を含む）÷ 25 を小数1桁に四捨五入して出す（「2.5」。整数は「4」）。25分未満は分で「12分」
- 差は、実績（小数1桁）と見積もりを比べる
  - 多ければ「+X（超過）」（見積もり超過の色）。少なければ「早く完了」（早く完了の色）。同じなら「±0」
  - 見積もりの `小` は「1以下」、`4` は「4以上」として比べる（`小` で 1 以下、`4` で 4 以上なら ±0）
  - 見積もりのない TODO は、見積を「—」、差を空欄にする
- 表の下の左に「単位：ポモドーロ（25分）」、右に「未完了のN件は、今日のリストに残したまま明日のリストへ複製されます」（N は今日やると着手中の数。0件なら出さない）

**日報を書く**
- 案内文「今日の実績と、作業ログから拾った出来事を材料として並べます。Good/Bad/Tryはあなたが書きます。」
- 材料の箇条書き
  - 「作業ログ：作業ログ/2026-11-03.md」。押すとヘッダーのリンクと同じく開く
  - 中断があれば「中断 N回」と、メモのある中断のメモ（中断の時刻は記録していないので、時間帯は出さない）
  - 見積もりの2倍以上かかった完了 TODO を「API設計レビューの指摘に対応は見積もりの2倍」の形で（倍率は小数1桁、整数は「2倍」。`小` は25分、`4` は100分として数える）
    - 倍率は表の実績（小数1桁）を見積もりで割って出し、小数1桁に丸めて2以上なら載せる（見積もり1で49分は、表の実績が2なので載せる。表と食い違わない）
- 「日報/YYYY-MM-DD.md を開く」ボタン。日報のフォルダ（設定）の同じ日付のファイルを開く。ファイルがなければ Obsidian が作る（作業ログと同じ）。**日報には書き込まない**

### M4 TODOを追加（ダイアログ）

- やること（テキスト）。開いたら入力欄にカーソルを置く。空白だけでは「追加」を押せない
- 見積もり：小（〜25分）／1（25分）／2（50分）／3（75分）／4+（100分〜）から選ぶ。**選ばなくてもよい**（7.5）。何も選んでいない状態で開き、選んでいるものをもう一度押すと外れる。選ばずに追加すると見積もりなしの TODO になる
- 「今日やる」の**いちばん下**に追加される
- 「追加」またはやることの入力欄での Enter で書き込み、書き込めたら閉じる。書き込めなかったときは知らせ、入力を残して開いたままにする
- 「キャンセル」・閉じるボタン・Esc では何も書かずに閉じる

### 設定画面

Obsidian の設定の「Daily Kanban TODO」。デザインのモックはなく、Obsidian の標準の設定画面の見た目にする。見出しは「フォルダ」「就業時間」「休憩」「通知」。

| 見出し | 項目 | 既定値 | 内容 |
|---|---|---|---|
| フォルダ | TODO のフォルダ | `TODO` | その日の TODO ファイル（YYYY-MM-DD.md）を置くフォルダ（7.1） |
| | 作業ログのフォルダ | `作業ログ` | ヘッダーの「作業ログ」から開くファイルを置くフォルダ |
| | 日報のフォルダ | `日報` | 終業の振り返り（M3）から開く日報を置くフォルダ |
| 就業時間 | 始まりと終わり | 9:00〜18:00 | タイムラインに描く範囲。集中できる時間もこの中で数える（8.2） |
| 休憩 | 休憩 1、休憩 2 … | 12:00〜13:00 の1つ | 集中できる時間から除く。「休憩を追加」で足し、ごみ箱で消す。なくてもよい |
| 通知 | 満了の音 | オン | 25分たったときに短い音を鳴らす。オフでも、消えない通知と OS の通知は出す（8.1） |

- **変えたらすぐに効く。** 保存のボタンはない。入力は打ち終えたとき（Enter や欄を離れたとき）に効かせる（打ちかけの値で読み直さない）。間違いは打っている間から欄の下に出す。TODO のフォルダを変えたら、保留中のタイマーは新しい置き場所のファイルで判定し直す。開いているボードは、TODO のフォルダや就業時間・休憩を変えるとその場で読み直し、タイムライン・ヘッダーの可能なポモドーロ数・集中できる時間を描き直す。作業ログのリンクと満了の音も、次に使うときから新しい設定で動く
- **正しくない入力は保存しない。** その欄の下に何が問題かを出し、直すまでは前の値を使う
  - フォルダ名が空（空白と `/` だけを含む）
  - 時刻が「9:00」の形でない（「09:00」と全角の「９：００」も読む。0:00〜23:59）
  - 終わりが始まりより後でない（就業時間・休憩）
  - 休憩が就業時間からはみ出す
- 就業時間と休憩は組み合わせで正しいかが決まるので、まとめて保存する。どこか1つでも問題があれば、就業時間も休憩も前の値のまま。足したばかりの空の休憩も、入力するか消すまでは問題として出す
- 休憩どうしは重なってもよい（集中できる時間では二重に除かない。8.2）
- フォルダ名の前後の空白と `/` は除く。フォルダを変えても、ファイルは移さない（新しいフォルダの同じ日付のファイルを読む）
- 保存した設定が読めない・一部が崩れているときは、崩れた項目だけを既定値にする

### テーマ（ライト／ダーク）

- 利用者が使っている Obsidian のテーマ（コミュニティテーマを含む）になじむ見た目にする
- モックは M1〜M4 の Tweaks で「ライト／ダーク」を切り替えて確認できる。下の表はモックの配色で、色の役割と意図を示す目安

## 6. 1日の流れ

1. **朝：** Claude に指示して、その日のファイルを作ってもらう（前日の未完了の複製、Googleカレンダーの予定、追加の TODO）。ボードを開き、予定のタイムラインと残り集中時間を見ながら、並べ替えて今日の順番を決める
2. **作業：** カードを着手中へ動かすとタイマーが始まる。25分で自動終了して通知が出て、作業時間が記録される。続けるときは「次のポモドーロを開始」を押す
3. **割り込み：** 「中断」で止めると、それまでの分数が「中断」として記録される。カードは着手中に残り、「次のポモドーロを開始」で再開する
4. **完了：** 「完了にする」（または完了列へ移動）でタイマーが止まり、経過分が記録される
5. **修正：** 押し忘れや途切れた作業は、M2 で分数を直す・足す
6. **終業：** M3 で見積もりとの差を確認し、日報ファイルを開いて本人が Good/Bad/Try を書く
7. **翌日：** 未完了は翌日のファイルへ複製される（当日のファイルはそのまま残る）

## 7. データ構造

基本方針：**1日1ファイルの Markdown に、確定した事実だけを書く。Markdown が唯一の正。**

### 7.1 ファイル配置

```
TODO/
  2026-11-03.md      ← プラグインが読み書き
作業ログ/
  2026-11-03.md      ← Claude と本人が書く（プラグインはリンクするだけ）
日報/
  2026-11-03.md      ← 本人が書く（プラグインは開くだけ）
```

- フォルダ名は設定で変更できる（既定は上のとおり。設定画面）。変えてもファイルは移さない
- 3つは**同じ日付のファイル名**でつながる

### 7.2 TODOファイルの形式

```markdown
---
date: 2026-11-03
events:
  - 10:00-11:00 定例
  - 14:00-15:00 API設計レビュー
---
- [/] 提案資料の構成を固める [est:: 3]
    - 25分 ポモドーロ
- [ ] API設計レビューの指摘に対応 [est:: 2]
- [ ] 見積もりの返信を書く [est:: 1]
- [x] 経費精算を提出 [est:: 小]
    - 12分 ポモドーロ
- [x] メールの返信 [est:: 1]
    - 25分 ポモドーロ
    - 12分 中断 チャットでの問い合わせ
    - 25分 手動
```

- **TODO 1件 ＝ トップレベルのチェックボックス1行**
- **行の順番 ＝ 優先度。** 列の中の順番は、同じ状態の行どうしの並び順
- プラグインがなくても Obsidian でチェックリストとして読め、Dataview でも集計できる

### 7.3 予定

frontmatter の `events` に、その日の予定を1件1行で書く。書くのは Claude（Googleカレンダーから取得）。

```
  - {開始 HH:MM}-{終了 HH:MM} {予定名}
```

- プラグインは読んで表示するだけで、書き換えない
- 終日の予定は書かない（タイムラインに載らないため）
- 書式から外れた項目は表示せず、そのまま残す
- 日中に予定が変わったら、Claude に頼んで書き直してもらう

### 7.4 状態

| 記号 | 状態 | 備考 |
|---|---|---|
| `[ ]` | 今日やる | |
| `[/]` | 着手中 | 同時に1件だけ |
| `[x]` | 完了 | |

カードを列間で動かす ＝ 行の記号を書き換える。

### 7.5 見積もり

行末の Dataview インラインフィールド `[est:: 値]`。値は `小` `1` `2` `3` `4`（単位はポモドーロ＝25分。`4` は「4以上」を表す）。省略してもよく、その TODO は見積もりなしとして扱う。

### 7.6 作業時間

TODO 行の子の行に、1件ずつ書く。

```
    - {分}分 {種類} {メモ（任意）}
```

| 種類 | 書く主体 | 意味 |
|---|---|---|
| `ポモドーロ` | タイマー | 25分の満了、または途中で完了したときの経過分 |
| `中断` | タイマー | 「中断」で止めたときの経過分 |
| `手動` | 本人（M2） | 手で追加・修正したもの |

- **実際の作業時間（実績）＝ 子の行の分数の合計。** 合計値は保存しない
- 例：「メールの返信」は 25＋12＋25 ＝ 62分

### 7.7 Markdown に書かないもの

| もの | 置き場所・扱い |
|---|---|
| 実行中のタイマー | Markdown には書かない。終わった時点で分数を確定して Markdown に書く。Obsidian を閉じても計測中の状態（対象TODOと開始時刻）は失われない |
| 実績の合計 | 子の行から毎回計算する |
| 予定の取得元 | Googleカレンダーへの接続はプラグインが持たない。Claude が取得して `events`（7.3）に書く |
| 設定（フォルダ名、就業時間、音のオン・オフなど） | Markdown には書かない |
| 日報への書き込み | しない。M3 から日報ファイルを開くだけ |

### 7.8 翌日への複製

その日のファイルは、朝に **Claude が作る**。下のルールは Claude が守るもの。Claude を使わない日のために、ファイルがないときボードに「今日のファイルを作る」ボタンを出し、押すと同じルールで複製だけを行う（自動では作らない）。

1. その日のファイルを作る
2. **直近の過去ファイル**から `[ ]` と `[/]` の行を、順番を保って複製する（週末を挟んでも直近のファイルから）
3. 状態は `[ ]` に戻す。見積もりは残す。作業時間の子の行はコピーしない。作業時間ではない子の行（メモなど、深く字下げした後続行）は一緒に複製する
4. 元のファイルは書き換えない（未完了のまま残る）

「今日のファイルを作る」ボタン（プラグインが作るとき）
- 今日のボードで、今日のファイルがないときだけ、「今日のファイルがありません」の下に出す。過去の日には出さない（過去の日は作れない。8.3）
- 直近の過去ファイルは、TODO のフォルダにある、今日より前の日付の `YYYY-MM-DD.md` のうちいちばん新しいもの
- 作るファイルは frontmatter の `date`（今日）と、複製した TODO だけ。`events` は書かない（予定は Claude が書く。7.3）。frontmatter・書式から外れた行・完了の行は複製しない
- 過去のファイルがない・未完了が0件のときも、frontmatter だけのファイルを作る（その後 M4 で足せる）
- 作れたら、そのままボードに出す。押したときにはもうファイルがあった（Claude が先に作った）なら、上書きせずに知らせ、あったファイルを出す。作れなかったら知らせる

## 8. 詳細な振る舞い

### 8.1 タイマー

タイマーの状態は「停止中」と「計測中」の2つ。計測中のタイマーは常に1つで、着手中のカード（`[/]`）に紐づく。

| きっかけ | 記録 | カード | タイマー |
|---|---|---|---|
| カードを着手中へ動かす | — | `[/]` になる | 計測開始 |
| 25分たつ | `25分 ポモドーロ` | **着手中に残る** | 停止。カードに「次のポモドーロを開始」ボタンが出る |
| 「次のポモドーロを開始」 | — | 着手中のまま | 計測開始 |
| 「中断（割り込み）」 | `{経過分}分 中断` | **着手中に残る** | 停止。「次のポモドーロを開始」で再開できる |
| 「完了にする」／完了列へ移動 | 計測中なら `{経過分}分 ポモドーロ` | `[x]` になる | 停止 |
| 計測中に**別のカード**を着手中へ動かす | 前のカード：`{経過分}分 中断` | 前のカードは**今日やるの先頭**へ戻り `[ ]` に。新しいカードが `[/]` に | 新しいカードで計測開始 |
| 停止中に別のカードを着手中へ動かす | — | 前のカードは今日やるの先頭へ戻る | 新しいカードで計測開始 |
| 着手中のカードを今日やるへ戻す | 計測中なら `{経過分}分 中断` | `[ ]` になる | 停止 |

- **25分の満了の知らせ：** クリックするまで消えない Obsidian 内の通知＋OS の通知（macOS の通知センターなど）＋短い音。文言には何のカードの25分が終わったかを入れる。OS の通知をクリックすると Obsidian が前面に出る。OS の通知の許可は、満了のときではなく計測を始めたとき（本人が画面を見ているとき）に尋ねる。音は設定でオフにできる（オフでも、消えない通知と OS の通知は出す）
- **満了を確定できなかったとき：** その日のファイルがない・書き込めないときは1回だけ知らせて保留にし、毎秒やり直さない。ファイルが変わったときか、次の操作で判定し直す
- **休憩：** ツールでは管理しない（休憩タイマーや自動再開はしない。自動再開は「止め忘れ」を生むため）
- **分の扱い：** 経過時間は分未満を切り捨てる。**1分未満は記録しない**
- **ボードを閉じていても進む：** Obsidian が動いていれば、ボードのタブを閉じていてもタイマーは進み、25分の満了で記録して知らせる
- **対象が見つからないとき：** 着手中の行（`[/]`）が見つからない・2件ある・文字列が違うときは、すぐには捨てずに保留にする。判定するのはタイマーを動かす操作と25分の満了のときだけで、保留中はファイルが変わるたびに読み直し、見つかれば続ける（25分を過ぎていれば確定する）。保留中の操作でも見つからなければ捨てて知らせる（記録しない）
- **Obsidian を閉じた・PC がスリープした場合：** 開始時刻から再計算する
  - 再開時に25分を過ぎていれば `25分 ポモドーロ` として確定し、停止する
  - 25分以内なら、そのまま続きから計測する
  - 実態と合わない記録は M2 で本人が直す

### 8.2 タイムラインと集中できる時間

- **就業時間を設定で指定する**（既定は 9:00〜18:00）。昼休みなどの休憩時間帯も設定できる（既定は 12:00〜13:00 の1つ）。休憩はいくつでも足せ、なくてもよい
- タイムラインの表示範囲は就業時間に合わせる
- 「この後、集中できる時間」＝ 現在時刻（就業前なら就業開始）から就業終了までのうち、予定と休憩を除いた時間。重なった予定や休憩は二重に除かない。25分で割ってポモドーロ数も出す（端数は切り捨て）
- 時間は 0.5時間刻みで切り捨てて「約 X時間」と出す（多めに見せない）
- 就業時間と休憩を変えたら、開いているボードのタイムラインと集中できる時間、ヘッダーの可能なポモドーロ数をすぐに描き直す

### 8.3 他の日のボード

| 日 | できること |
|---|---|
| 今日 | すべての操作 |
| 過去 | 閲覧と、作業時間の修正（M2）だけ。追加・並べ替え・状態の変更はできない。ボードを開いたまま日付をまたいだときは、その日の計測を「中断」で止められる（経過分を記録するだけで、作業時間の修正と同じ扱い） |
| 未来 | 開けない（翌日への移動ボタンは今日で止まる） |

- 前日・翌日への移動は暦の上の1日ずつ。ファイルのない日も飛ばさずに開き、ファイルがないことを出す（休みの日を飛ばすには、ほかの日のファイルを探す必要がある。ヘッダーの日付と見比べて分かればよい）
- 日を切り替えると、開いている M2・M4 のダイアログは閉じる（前の日のボードに書き込ませない）

### 8.4 Markdown を直接編集した場合

- Markdown を直接編集すると、その内容がボードに反映される
- **書式から外れた行は無視してそのまま残す。** ボードには出さず、プラグインがファイルを書き換えるときも消さずに元の位置に保持する

### 8.5 書式についての決定

- 着手中の記号は `[/]` のまま進める。標準の Obsidian では完了のように表示されることがあるが、ボードで操作する前提なので許容する。問題が出たら見直す
- 作業時間の書式は日本語（`25分 ポモドーロ`）のまま進める。人と Claude の読みやすさを優先する
- 「作業ログ」の書式は自由。プラグインはリンクするだけで、中身は読まない
- TODO 行は、字下げなしの `- [ ]` `- [/]` `- [x]` で始まる行だけ。`[X]`、`[-]`、`*` や `1.` で始まるチェックボックスは書式外の行として残す
- 作業時間の行を書き足すときの字下げは、そのブロックの既存の子の行に合わせる。子の行がなければスペース4つ

### 8.6 カードを動かしたときの位置

| 操作 | 入る位置 |
|---|---|
| ドラッグで並べ替える・列を移す（着手中以外） | ドロップした位置 |
| 着手中へ動かしたカード | Markdown の行は元の位置のまま、記号だけ変わる（着手中は1件なので列の中の位置はない） |
| 「完了にする」ボタン | 完了の末尾 |
| 計測中・停止中に別のカードを着手中へ動かしたときの前のカード | 今日やるの先頭（8.1） |
| TODO の追加（M4） | 今日やるの末尾 |
